# RE and symbol-map workflow

Moved out of the root `CLAUDE.md`.

## Commands

| Task | Command |
|------|---------|
| Mirror cooked assets to `data/uncooked/` | `python scripts/extract_uncooked.py` (textures → PNG, everything else copied; sound banks come from `audio_pairs()`, not the CSV). **The mirror is pruned to match**: anything the run did not write is deleted, so a renamed asset cannot leave its old spelling behind (that is what made the 2026-09-22 cipher fix break `test_poi.py` with a GUID collision). `--prune-dry-run` to preview, `--no-prune` to skip; a `--limit`/`--filter`/errored run never prunes, since it only describes a slice. `Audio/extracted/` (extract_audio.py) and live `.gen.txt` sidecars (decode_gen_sidecars.py) are exempt |
| Unpack sound banks to playable audio | `python scripts/extract_audio.py` (`--wav`, `--filter <Bank>`) — needs `pip install fsb5`; writes `data/uncooked/Audio/extracted/<Bank>/<Sample>.ogg` |
| Triage a loader crash | `python scripts/triage_dump.py` (newest dump; stdlib-only) — exception + fault symbol + stack scan (game VAs + nm-symbolized loader frames) |
| Disassemble the live exe (no Ghidra) | `python scripts/disasm.py <game_va> [n]`, `--resolve NAME`, `--whatis <va>`, `--calls NAME` — capstone over Ravenswatch.exe with symbol annotation |
| Verify symbol addresses vs live exe | `python scripts/verify_symbol_resolve.py` (after any remap; also auto-runs as a fail-closed gate in `install-loader`) |
| Audit what the loader ACTUALLY resolved | `rsmm symbols audit` (after a launch with the `RSMM_DUMP_SYMBOLS` flag → `<game>/rsmm/resolved_symbols.json`) |
| Stamp patch-survivable symbol fingerprints | `python tools/mine_fingerprints.py` (writes `data/symbol_fingerprints.json`); `--verify` reports how many re-find uniquely by content — run after RE sessions so symbols auto-remap next patch |
| Find unnamed engine INTERFACE methods | `python tools/mine_vtable_interfaces.py [--family Definition]` — diffs vtable slots across sibling classes. A slot the base stubs out and many subclasses each override with a DIFFERENT body is an abstract method worth naming; naming one lights up every call site through that slot at once. Ranking by "most shared function" finds the opposite (no-op stubs — one appears in 4153 vtables). Found `IsUnlocked` (slot 14, unlock-condition family) and all 13 `PostLoad` implementations (slot 18, Definition family) |
| Relocate `status=va` data globals after a patch | `python tools/va_locators.py capture` on the KNOWN-GOOD build (writes gitignored `data/va_locators.json`; refuses to overwrite one captured from another build), `verify` (identity on that build), then on patch day `recover --exe <new> [--apply]`. Two locator kinds: **rtti** (a vftable is re-found by its RTTI class name + subobject offset) and **ref** (an EXACT `[rip+disp]` read inside a function re-found by a pattern that matches once — the DB's, or one grown with `make_pattern` until unique). `--apply` writes only globals with ≥2 agreeing votes and no dissent. Captured 2026-10-11 on 40430b75c72b: 46/51 recoverable (44 auto, 2 single-site `P2PSession_StateNames`/`g_MagicalObjectComponentMeta` need a hand check); the other 5 are the globals the 2026-09-17 audit found UNREFERENCED — already stale, and nearby-address refs were deliberately dropped because they "recovered" one of them by proximity. |
| Relocate stranded symbols after a patch | `python tools/recover_unverified.py [--apply]` (uses note anchors); `data/symbol_fingerprints.json` is the richer content locator |
| Open the Ghidra project (there is ONE) | **`ghidra_project/Ravenswatch-New`** (gitignored, ~765 MB) — this is what `tools/ghidra_mcp/serve.sh` (pyghidra-mcp, Ghidra 12 — the project is in 12 format since 2026-10-10, so 11.3 cannot open it) serves, and what `<projdir>` must mean in every headless command below. Every other copy (the same-named `rsmm_ghidra_headless/Ravenswatch-New`, `docs/_re/project/RSMM*`, the `ghidra_project.bak-*` backups) was deleted 2026-10-11; `rsmm_ghidra_headless/` now holds only BinExports and pre-patch snapshots. On patch day import the new exe into this project as a SECOND program — never re-import over the old one, which is the only "old" side with names. Stop `serve.sh` (Ctrl+C saves) before any headless run, since it holds the project lock. |
| Relocate symbols whose BYTES changed (patch day) | `tools/bindiff_remap.py <old_vs_new.BinDiff> [--apply]`. Three steps: export each build with `analyzeHeadless <projdir> <proj> -process Ravenswatch.exe -noanalysis -readOnly -scriptPath tools/ghidra_scripts -postScript BinExportHeadless.java /tmp/<n>.BinExport` (the project must be UNLOCKED — close the GUI/MCP bridge; and `MAXMEM=2G` in `analyzeHeadless` OOMs on this exe, so invoke `support/launch.sh fg jdk Ghidra-Headless 6G "" ghidra.app.util.headless.AnalyzeHeadless …` instead), then `bindiff --primary=old --secondary=new --output_dir=/tmp`, then the remap. Installed userland (no sudo): `~/.local/opt/bindiff` on PATH, extension copied out of the .deb's `extra/ghidra/BinExport` (its `extension.properties` ships no `ghidraVersion`, so one was added). The pre-patch baseline export is `rsmm_ghidra_headless/Ravenswatch-<exe-sha12>-<date>.BinExport` (current: `Ravenswatch-40430b75c72b-20261011.BinExport`) — never in git, it is game-derived. The project is Ghidra-12 format, so run the export with `../ghidra_12.1.4_PUBLIC/support/launch.sh …` (not 11.3). BinExport for 12.1.4 lives in `~/.config/ghidra/ghidra_12.1.4_PUBLIC/Extensions/BinExport`: it is the same 2023 jar (built for 10.3.3) with `ghidraVersion` relabelled — proven 2026-10-11 by a same-build self-diff (74,229 functions matched, 99% confidence). If a Ghidra upgrade breaks it, relabel again or fetch a newer google/binexport build. ⚠ BinExport can only export what Ghidra has defined as a FUNCTION, so a symbol whose address Ghidra never turned into a function (15 of them on 2026-09-08, incl. `HeroStats_OnDamageTaken`, whose bounds came from `.pdata`) is unmatchable — that is a gap in this pipeline, not a finding about the patch, and the tool separates the two buckets. This is the complement to the pattern DB, not a replacement: patterns re-find a symbol whose bytes SURVIVED, BinDiff matches on call-graph/basic-block structure and finds the ones that were recompiled or re-inlined. `--apply` rewrites only `raw`, never `status` — a relocated address is a hypothesis until `rsmm symbols gen && python scripts/verify_symbol_resolve.py` |
| Bring a new build's Ghidra program up to date (patch day, after import) | A fresh import has NONE of our names, notes or types (measured 2026-10-16 on b9c3: 0 names, 1,309 types vs the old program's 12,620). With the project UNLOCKED (stop `serve.sh`; back up `ghidra_project/` first — writes are not undoable): (1) `python tools/ghidra_apply_knowledge.py -o k.json [--bindiff old_vs_new.BinDiff --old-tag <sha12>]` then `launch.sh fg jdk Ghidra-Headless 6G "" ghidra.app.util.headless.AnalyzeHeadless ghidra_project Ravenswatch-New -process <prog> -noanalysis -scriptPath tools/ghidra_scripts -postScript ApplyRsmmKnowledge.java k.json [dry]` — defines missing `.pdata` functions, names every ok/va symbol with its note as the plate comment (shows in every decompile). BinDiff ports only add ~20 CRT names: the old program's real knowledge IS symbols.json. (2) export the NEW build's corpus (`scripts/ghidra_scripts/ExportDecompiled.java` + `ExportVftables.java`, on a project copy) into `docs/_re/out_new/` and restamp `corpus.meta.json` — `recover_unverified.py`, `gen_ghidra_vtables.py` and the miners read it, and a stale one gives confident wrong addresses. (3) `python tools/gen_ghidra_vtables.py --game-only --corpus docs/_re/out_new -o rsmm_vtables.py` and run it with **`support/pyghidraRun --headless`** — ⚠ Ghidra 12 ships NO Jython, so every `.py` script needs PyGhidra; set `VIRTUAL_ENV`/`PATH` to `~/.local/share/rsmm-pyghidra-venv` (offline install from `Ghidra/Features/PyGhidra/pypkg/dist`), or pyghidraRun installs into whatever venv is active (it polluted `.venv-build` once). |
| "Who wrote this byte" (hardware watchpoint) | `R.watch.on(va, {len=4, label="hp"})` → play → `R.watch.report()` → feed the printed VA to `scripts/disasm.py --whatis`. Needs `RSMM_ENABLE_WATCH=1`. DR0-DR3, so **four slots in the whole CPU**, and they are PER-THREAD — a thread the game creates after arming carries none (`R.watch.rearm()`). The address must be aligned to its length or the CPU never fires it and the answer reads as "nothing wrote it". Debug tool only: a process-wide vectored handler plus debug registers is what an anti-tamper check looks for |
| Type vtable structs + this-params (headless) | `python tools/gen_ghidra_vtables.py --game-only -o rsmm_vtables.py` (writes .py+.json) → `ghidra_12.1.4_PUBLIC/support/analyzeHeadless <projdir> <proj> -process -noanalysis -scriptPath /tmp -postScript rsmm_vtables.py rsmm_vtables.json` (project must be UNLOCKED — close GUI/MCP, or copy the .rep). Creates the structs MCP cannot. Phases 3-5 type each unambiguous slot func's `this` (and, for ctors / `return param_1;` funcs, the RETURN) to `<Class>*`, so `(**(code**)(*this+0xNN))` decompiles as `this->vftable->Target()`. **Params are committed via `HighFunctionDBUtil.commitParamsToDatabase(hf, True, NO_COMMIT, USER_DEFINED)` BEFORE retyping param 0** — the earlier `updateFunction(..., DYNAMIC_STORAGE_FORMAL_PARAMS, [this])` shortcut commits exactly ONE param and deletes all the others (it damaged the real project on 2026-07-18; reverted from backup). Object structs are SIZED from the largest observed `param_1 + 0xNN` (`mine_obj_sizes`): Ghidra scales pointer arithmetic by pointee size, so an 8-byte object renders a real `+0x288` as a misleading `+0x51` and invents `param_1[0x26a].vftable` array reads. MEASURED (666-func sample, sized + commitParams, 2026-07-18): unresolved `(**(code **)` vcalls 1645→**1094 (−33.5%)**, 624 resolved `vftable->` refs, committed params 0→1400, `in_R??` leakage flat at 3, zero storage-locked warnings. ⚠️ Do NOT measure this with a `code *` string count — a resolved vcall still prints the `(code *)` cast, and the 8-byte config lowers the count via fake array renderings. Count `(**(code **)` (unresolved) and `vftable->` (resolved) instead. |

## New-capability workflow

Applies to any subsystem with no `status="ok"` symbol in `data/symbols.json` yet. Capability classes that already have a dedicated miner — event names (`tools/mine_event_names.py`), event payloads (`tools/mine_event_payloads.py`), vtable interface methods (`tools/mine_vtable_interfaces.py`), class ids (`tools/mine_class_ids.py`) — skip to step 5; for those the mining IS the recon.

1. **Check the map before doing any RE.** `rsmm symbols list` / `rsmm symbols resolve <Name>`, and grep the `note` prose in `data/symbols.json` — 191 symbols, most carrying a paragraph of hand-RE, including the ones that were tried and shelved. `docs/SYMBOLS.md` and `apps/docs/.../reference/symbols.md` are the same map rendered. A "new" subsystem is often one `unverified` entry away from working.
2. **Static recon anchored to a symbol you already trust**, never a cold read of an isolated function that looks like the right thing. `scripts/disasm.py --resolve <Name>` lands inside a known function, `--calls <Name>` lists its callees, `--whatis <va>` names whatever you drifted into. `tools/symbol_locate.py` exists because the opposite approach produced confident wrong answers: scoring every function in the corpus handed `Netcode_DropPeer` its *caller* (the note's quoted string is logged one frame up) and gave three unrelated symbols the same 1234-line level-load orchestrator. Constrain to a handful of candidates first (vftable class+slot; callers/callees of an already-located symbol; the functions called *next to* a string's use), then discriminate inside that pool only.
3. **Dynamic proof against a known-good trigger is a gate, not a formality — it comes before any code is written.** Static reading gets the shape; only the running game gets the address. Launch with `RSMM_DUMP_SYMBOLS=1` in the loader flags and diff the result with `rsmm symbols audit`, which flags any `status=ok` symbol the loader resolved to null or to non-prologue bytes. For a struct, walk a live instance with `R.debug.dump` / `R.debug.find_arrays` / `R.debug.strings`, which turn multi-launch struct-hunting into one launch. Native `read_*` is page-guarded so probing is free — but the moment a probed pointer becomes a call argument the engine owns the deref, so validate with `R.ptr.*` and call through `R.engine.call_safe`.
4. **Look for the second gate before declaring victory** — verify the end-to-end effect, not that the call fired. Canonical case: POIs. A mod tiledef needs a sibling `.UsedRscCache.ot` or it is registered and never placed; fixing every per-tile cache still left the POI invisible for another playtest, because the *mapdef's own* cache gates its pool one-for-one. Both gates fail silently and neither logs anything, so "the tile registered" proved nothing.
5. **Only then write the symbol entry, regen, and build the SDK-side capability.** `status` is not a label you pick: `rsmm symbols check` fails an `ok` whose pattern is absent from `data/function_patterns.json`, so `ok` is *earned* by `scripts/gen_function_patterns.py` → `scripts/sync_symbol_patterns.py`; follow with `rsmm symbols gen` and `python scripts/verify_symbol_resolve.py`. If the symbol was found by a hand-derived anchor (vftable class+slot, a callgraph neighbour, a quoted string), record it as a structured `locator` — `tools/backfill_locators.py --apply`, and `--check` asserts it still resolves — because that is what stops the next game patch from being another manual session. The deliverable is a kind builder, an engine cooker, or an `R.*` API, never a bespoke script: `rsmm lint` fails any `*.py` in a mod that isn't `on_disable.py`, and ERRORs on a literal `0x14xxxxxxx` or on `_internal`/`peek`/`poke`/`read_*`/`write_*`/`call_raw`/`engine.resolve` in mod Lua. For a content kind, set an honest `KIND_CONFIDENCE` rating — anything below `confirmed` forces `sdk.Mod(..., experimental=True)`.
6. **Park ruled-out hypotheses as `unverified` entries with the reasoning in `note`** (the field is `note`, singular). A hypothesis that cost a session to eliminate is worth as much as one that worked, and only the map remembers it. `LobbyMembers_List` is the shape to copy — full member layout, then "⚠ The caller OWNS the returned members and destroys each one … The damage meter does not need to", so the next session reads why not to call it instead of re-deriving it. Parking is safe by construction: `validate()` fails a non-`ok` symbol that still has a pattern in the DB, so an `unverified` entry cannot be resolved or hooked by the loader.

## Engine symbol map

**Engine symbol map (Minecraft-style mappings).** `data/symbols.json` is the canonical, human-authored map from semantic names (`MagicalObject_SpawnAllObjects`) to engine functions/globals — the source of truth. The Ghidra DB names, the loader C++ header (`src/loader/include/symbols.gen.h`), and the Python constants (`src/rsmm/engine/_symbols_gen.py`) are all GENERATED from it via `rsmm symbols gen` (CI `--check`s freshness). Resolution forms, most to least version-resilient: `raw` (`FUN_<addr>` whose byte pattern is in `data/function_patterns.json`, so the loader re-scans across game updates), `anchor` (inlined routine = parent pattern + offset), `va` (base-relative absolute for data globals). Each symbol carries a `status`: `ok` (pattern/anchor resolvable now), `va`, or `unverified` (documented in an older corpus, address not re-confirmed — these are skipped by `rsmm symbols ghidra-export` unless `--include-unverified`). Don't hardcode engine addresses in the loader or SDK; add a symbol and reference `Sym::Name` / `ADDR["Name"]`. To stop functions reading as `FUN_xxxxxxxx` in your own Ghidra, run `rsmm symbols ghidra-export` and apply the script (or feed the `--json` table to the Ghidra MCP bridge). Layers generated on top of the map (the Minecraft Forge/Fabric analogs): (1) **callable typed API** — a symbol with a `cabi` (ret + params) gets a typed, pattern-resolved C++ accessor `engine::Name()` (`src/loader/include/symbols_api.gen.h`) so you call named functions instead of casting raw addresses, plus a Lua resolver `engine_gen.lua`; (2) **event bus** — symbols with `kind="event"` + `lua_event` generate the `EventHook` table spliced into `hook_events.cpp` (`event_table.gen.h`); mods subscribe via `R.on("<lua_event>", cb)`, browse with `rsmm symbols events`; (3) **Lua high-level API** — `R.engine.resolve(name)` / `R.engine.call(name, ...)` in `rsmm.lua` resolve by semantic name through the native `_internal.resolve`/`call`; (4) **engine API docs** — `docs/SYMBOLS.md` (Javadoc analog). All six generated artifacts are `rsmm symbols gen --check`'d in CI.

Three symbol-map caveats that CI does NOT catch: (1) `data/function_patterns.json` is **gitignored** (14 MB, game-derived) — regenerate locally via `scripts/gen_function_patterns.py` / `scripts/add_function_patterns.py`; users receive it through `rsmm update-data` from the rolling `pattern-db` GitHub release (publish with `scripts/publish_pattern_db.sh` — must be run by a human, and the running game reads the planted copy at `<game>/rsmm/data/`, not the repo's). (2) `symbols gen --check` validates artifact consistency only, never that an address is CORRECT — after any remap run `scripts/verify_symbol_resolve.py` against the live exe. (3) Addresses alone are still emitted for every symbol, so a `va` global remains reachable by design and must stay gated on `va_globals_trusted`; only pattern-backed resolution is fail-closed. `data/symbols.json` is serialized with `indent=1`; keep it that way or diffs explode.

**Symbol-correctness is now gated three ways** (built to end the false-ok class): `scripts/verify_symbol_resolve.py` disassembles where each status=ok pattern resolves in the live exe and fails on a non-function-start — and `install-loader` runs it as a fail-closed pre-plant gate on a dev checkout (skips on frozen/no-capstone/no-exe; `--force` overrides). For ground truth from the RUNNING game, launch with the `RSMM_DUMP_SYMBOLS` loader flag → the loader writes `<game>/rsmm/resolved_symbols.json` (name → resolved VA → prologue bytes), then `rsmm symbols audit` flags any status=ok symbol the loader resolved to null or to non-prologue bytes. To inspect any address without Ghidra, `scripts/disasm.py` disassembles the live exe and resolves call targets to semantic names via the pattern DB.
