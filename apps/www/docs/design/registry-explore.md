# Registry explore surface

The `/registry` page follows the user's Airbnb browsing reference: a centered search field below the global header with an integrated Filters control, and mod cards spanning the available page width. There is no map or filter sidebar. RSMM's existing warm dark palette, Alegreya Sans controls, parchment text, crimson actions, and blackletter wordmark remain authoritative. Across the website, the sticky global header uses a dark scrim and 20px backdrop blur, masked into a soft gradient extending 28px below the header instead of a bottom border. The fade is a separate, noninteractive layer so navigation and menus stay sharp and controls below remain clickable.

This is an Operate surface: find a mod, narrow the results, then open or download it. The global header retains its normal navigation, version, source, and account controls. The chosen Centered toolbar sits directly beneath it, with the result count on the left, search in the center, and sort/view controls on the right. Only the global header stays sticky. The toolbar is in normal document flow and scrolls away with the cards, avoiding the independent movement of a fixed search row during macOS overscroll. Its background and backdrop blur fade into the page through a gradient mask, with no bottom border. The toolbar keeps a consistent height: 85px on desktop, 141px on tablet, and 129px on phones. Below 1100px, search moves to a full-width second line inside the toolbar. Result scrolling accounts only for the sticky global header. Long result headings truncate visually while retaining the full accessible text and title.

The search field places the magnifying-glass submit control on the left and a Filters button inside the right end. Filter options are available in the modal instead of exposed shortcut chips. An active-filter count sits on the Filters button without changing its size or the row's height. The result count, search, sort, and retained card/list preference share the toolbar. The default card grid uses the full width, growing from one column on phones to a maximum of four columns on larger screens. Registry and homepage cards both render the shared `ModCard` component, using Airy’s unframed layout with Editorial’s typography and spacing: a rounded 16:9 image area (also used for generated covers), no card background or border, badges above a 20px serif title, a short summary directly under the title in the primary text color (up to three lines), then an italic serif author byline; both summary and author are 16px. Both pages keep a maximum of four cards per row. Space separates cards and metadata without divider lines. The left-aligned stats row shows downloads first, followed by a subdued dot and the average rating with its count, such as “↓ 565 · ★ 5.0 (15)” (the downloads label is screen-reader-only). Unrated mods omit the star, rating text, and separator. Hidden download counts remain omitted; the dot appears only when both stats are shown. Cards omit version numbers. The list API supplies ratingCount from the mod’s reviews; older responses may omit the count until the API rollout is complete. The tag row contains at most two labels: “Private games only” first when present, styled with a gilt warning icon and tinted background matching the detail page, then the mod category. Other tags are omitted from cards. Featured and mature-content indicators remain separate on the artwork when applicable. Existing generated covers fill missing-image states; download and app actions remain available on the detail page and in list view.

Filters opens a native modal dialog with categories, available tags and counts, minimum rating, and preferences for hiding private-only mods, featured-only results, and mature content. Section headings and preference labels have no explanatory subtext. Private-only tags (including legacy aliases) are omitted from tag choices; the “Hide private only mods” preference excludes them on the server before pagination and applies to result totals and facet counts. Retired private-only tag selections in shared URLs are ignored rather than left as invisible filters. Changes remain local to the dialog until Show mods applies them together. Clear all resets the draft; closing by the close button, Escape, or backdrop discards it. The dialog traps focus, restores it on close, locks background scrolling, and keeps its header and actions visible while its body scrolls. On mobile it sits at the bottom of the viewport with safe-area padding.

Search is debounced by 300ms and can also be submitted. Applied state lives in the URL, preserving shared searches and browser navigation. Changing search, sorting, or filters restarts pagination. Clearing filters keeps search and sort; resetting an empty result clears the whole search. Server-side filtering, pagination, and mature-content exclusion remain in place. These changes require no new API endpoints or dependencies.
